# 微软拼音「用户自定义短语」文件格式（mschxudp）

本文档记录本项目实测得到的格式细节。所有结论都标注了证据来源，
区分「本机实测」与「社区逆向资料」两类。

目标文件：

```
%APPDATA%\Microsoft\InputMethod\Chs\ChsPinyinEUDPv1.lex
```

该文件在**第一次添加自定义短语时才会生成**。未添加过的机器上不存在。

---

## 1. 文件头

| 偏移 | 长度 | 内容 | 说明 |
|---|---|---|---|
| `0x00` | 8 | `6D 73 63 68 78 75 64 70` | 魔数，ASCII `mschxudp` |
| `0x08` | 8 | `02 00 60 00 01 00 00 00` | 版本 |
| `0x10` | 4 | uint32 | 偏移表起点，本实现固定 `0x40` |
| `0x14` | 4 | uint32 | 记录区起点 = `0x10` 的值 + `4 × 条目数` |
| `0x18` | 4 | uint32 | 文件总长（字节） |
| `0x1C` | 4 | uint32 | 条目数 |
| `0x20` | 4 | uint32 | 时间戳（Unix 秒） |
| `0x24`–`0x3F` | 28 | `00` | 补零 |

## 2. 偏移表

位于 `0x40`，每条记录 4 字节 uint32，值为**该记录相对记录区起点的偏移**。

- 第 `i` 项 = 第 `i` 条记录的起始偏移
- 第 0 项恒为 `0`
- 自洽性约束：`offset_start + 4 × count == phrase_start`

## 3. 记录

每条记录紧跟上一条，无填充：

| 相对偏移 | 长度 | 内容 |
|---|---|---|
| +0 | 4 | 魔数 `10 00 10 00`（小端 uint32 = `0x00100010`） |
| +4 | 2 | uint16 = **编码字节数 + 18**（编码为 UTF-16LE，故字节数 = 字符数 × 2） |
| +6 | 1 | 候选位，1..9 |
| +7 | 1 | 恒为 `0x06` |
| +8 | 4 | 保留，实测为 0 |
| +12 | 4 | 时间戳（Unix 秒） |
| +16 | 变长 | 编码，UTF-16LE，以 `00 00` 结尾 |
| … | 2 | `00 00` 编码终止符 |
| … | 变长 | 词面，UTF-16LE，以 `00 00` 结尾 |
| … | 2 | `00 00` 词面终止符 |

记录总长 = `16 + 编码字节数 + 2 + 词面字节数 + 2`，必须与偏移表差值一致。

## 4. 硬限制

| 项 | 上限 | 来源 |
|---|---|---|
| 编码长度 | 32 字符 | 社区工具（imewlconverter / PinyinLexTool） |
| 词面长度 | 64 字符 | 同上 |
| 候选位 | 1..9 | 字段为 1 字节，UI 只暴露 9 个坑位 |
| 总条数 | 约 20000 | 社区工具；超出部分导入即被截断 |

编码字符集：`a-z` 与 `'`。不以 `u`/`v` 开头（那两个是微软拼音的模式键）。

## 5. 排序要求

**记录必须按编码升序排列。**

社区脚本（`fix-ms-input-pinyin-phrase.py`）中有明确注释：

```python
# Necessary fix, otherwise the order of phrases will be messed up.
phrase_list.sort(key=lambda x: x[1])
```

本项目实测复现了违反此约束的后果：条目乱序时，输入法完全匹配不到自定义短语，
候选列表里只剩普通候选。

## 6. 解析陷阱

UTF-16LE 下 ASCII 字符的高字节就是 `0x00`，因此编码串末尾的 `00 00` 终止符
会被前一个字符的高字节**提前命中**——`... 6F 00 | 00 00` 这段字节里，
第一处 `00 00` 出现在字符高位字节上，比真正的终止符早一个字节。

正确做法：**用 +4 处的长度字段定位编码**，不要靠扫描 `00 00` 找编码边界；
词面的边界则要在编码终止符之后按 2 字节步进扫描。

## 7. 与自学习词库的区别

| | `ChsPinyinEUDPv1.lex` | `ChsPinyinUDL.dat` |
|---|---|---|
| 作用 | 用户自定义短语（显式映射） | 自学习词库（被动记录用过的词） |
| 结构 | 偏移表 + 顺序记录 | 204 槽定长哈希表，每条 60 字节 |
| 魔数 | `mschxudp` | `55 AA 88 81` |
| 键 | 完整编码，1..32 字符 | 简拼，1..4 字母（实测分布：2 字母 21 条，3 字母 178 条） |
| 能否程序写入 | **可以，本项目已验证** | **不可行**：哈希函数未知，204 槽已用 199 槽 |

自学习词库由 `ChsIME.exe` 独占维护并持续回写，本项目只读不写。

## 8. 写入与生效

写入 `ChsPinyinEUDPv1.lex` 后，**不需要重启输入法**。本项目实测：
`ChsIME.exe` 自 2026-11-13 起持续运行未重启，在写入文件后立刻能打出新词。

失败模式与恢复：

- 格式非法 → 输入法忽略该文件，候选列表只剩普通候选（可恢复）
- 条数过多 → 微软拼音设置页「添加或编辑自定义短语」无限卡死，
  删除 `ChsPinyinEUDPv1.lex` 即可恢复（社区多次验证）
- 文件被 `ChsIME.exe` 占用 → 写入失败，本项目实现为「排队等下次部署」

## 9. 本项目对格式的改动

本项目在社区格式基础上只做了一处必要修正：**写入前按编码升序排序**，
其余字段布局、时间戳语义、终止符约定完全按上表。
